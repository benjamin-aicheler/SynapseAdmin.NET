## 🚨 1. Security & Vulnerabilities

*Focus: Hardcoded secrets, injection risks (SQL, XSS, Command), path traversal, insecure dependencies, authorization bypass.*

**Issues Found:**
* **Cookie-Session Sync Claims Mismatch:**
  In [MatrixAuthenticationStateProvider.cs:L98-L99](file:///home/benjamin/source/SynapseAdmin.NET/src/SynapseAdmin/Services/MatrixAuthenticationStateProvider.cs#L98-L99), during `LoginAsync` and `LoginWithTokenAsync`, the generated `ClaimsPrincipal` is missing the `AccessToken` claim. While the token is available during session restoration (via `GetAuthenticationStateAsync`) and in the cookie (issued in `AuthController.SignIn`), missing it from the initial principal can lead to bugs if components check the current HTTP request user claims immediately after login before a page reload.
* **Docker Container Execution Privileges:**
  The [Dockerfile](file:///home/benjamin/source/SynapseAdmin.NET/src/SynapseAdmin/Dockerfile) does not specify a non-root user. The runtime stage runs as `root` in the Docker container, violating the security principle of least privilege.
* **Default Passphrase in Docker Compose:**
  In [docker-compose.yml:L12](file:///home/benjamin/source/SynapseAdmin.NET/docker-compose.yml#L12), the environment variable `DP_PASSPHRASE` defaults to a hardcoded string `your-secure-passphrase-here`. Although there is a warning comment, this can easily lead to weak cryptographic configurations in production if not overridden.

**Recommended Fixes:**
* Add `new Claim("AccessToken", sessionService.Gateway.AccessToken)` to both login paths in [MatrixAuthenticationStateProvider.cs](file:///home/benjamin/source/SynapseAdmin.NET/src/SynapseAdmin/Services/MatrixAuthenticationStateProvider.cs).
* Add `USER app` at the end of the runtime stage in [Dockerfile](file:///home/benjamin/source/SynapseAdmin.NET/src/SynapseAdmin/Dockerfile) to run the container as a non-root user.
* Document and strongly enforce in the deployment docs that `DP_PASSPHRASE` must be supplied via a Docker Compose `.env` or external secret manager.

*Focus: Edge cases, Null-Reference risks, race conditions, off-by-one errors, infinite loops, incorrect async/await usage.*

**Issues Found:**
* **Mismatched Default Parameter Values:**
  In [IMatrixGateway.cs:L63](file:///home/benjamin/source/SynapseAdmin.NET/src/SynapseAdmin/Interfaces/Gateways/IMatrixGateway.cs#L63), the default value for `maxBytes` in `DownloadMediaAsync` is `3 * 1024 * 1024` (3MB), but in [MatrixGatewayBase.cs:L27](file:///home/benjamin/source/SynapseAdmin.NET/src/SynapseAdmin/Infrastructure/Gateways/MatrixGatewayBase.cs#L27) it is `5 * 1024 * 1024` (5MB). * **Fragile MXC URI String Parsing:**
  In [MediaService.cs:L72](file:///home/benjamin/source/SynapseAdmin.NET/src/SynapseAdmin/Services/MediaService.cs#L72), manual parsing via `mxc.Replace("mxc://", "").Split('/')` is used. This can fail or produce unexpected results if the MXC URI contains query parameters or does not have exactly two parts after the scheme.

**Recommended Fixes:**
* Change default value in `MatrixGatewayBase.cs` to match the interface's value (`3 * 1024 * 1024`) or remove the default value from the implementation to inherit the interface contract.
* Use `LibMatrix.StructuredData.MxcUri.Parse(mxcUri)` for parsing, or delegate parsing to the gateway tier entirely.

  In [RoomService.cs:L111](file:///home/benjamin/source/SynapseAdmin.NET/src/SynapseAdmin/Services/RoomService.cs#L111), `GetMediaMetadataBatchAsync` utilizes `Task.WhenAll` on a list select without concurrency limit.
