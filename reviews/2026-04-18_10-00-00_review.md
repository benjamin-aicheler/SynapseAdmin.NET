## 🚨 1. Security & Vulnerabilities

*Focus: Hardcoded secrets, injection risks (SQL, XSS, Command), path traversal, insecure dependencies, authorization bypass.*

**Issues Found:**
* **`MatrixGatewayBase.cs` (Line 38):** `DownloadMediaAsync` may download large files into memory if `Content-Length` header is missing or spoofed, potentially leading to memory exhaustion (OOM) on the server.
* **`AuthController.cs` (Line 18):** `SignIn` consumes the session bridge key. The bridge key is a GUID, which is reasonably secure for a short-lived (60s) one-time use, but the system relies on `IMemoryCache` which could be cleared (e.g. app restart) leading to login failures.

**Recommended Fixes:**
* In `DownloadMediaAsync`, use a stream-based approach with a byte counter to abort the download if it exceeds `maxBytes`, rather than relying solely on `Content-Length`.

## 🐛 2. Bugs & Logic Errors

*Focus: Edge cases, Null-Reference risks, race conditions, off-by-one errors, infinite loops, incorrect async/await usage.*

**Issues Found:**
* **`MatrixSessionService.cs` (Line 115):** If `AuthenticatedHomeserver` is not a `AuthenticatedHomeserverSynapse`, the `Gateway` is set to `null`. While `UserService` checks for null, other future services might not, leading to `NullReferenceException`.
* **`UserService.cs` (Line 92):** The avatar download logic handles exceptions but stores the result directly in the ViewModel. Large avatars could bloat the server-side memory for active Blazor circuits.

**Recommended Fixes:**
* Consider implementing a generic `MatrixGateway` for non-Synapse servers to avoid `null` returns, or ensure all services rigorously check for `Gateway != null`.
* Implement a media proxy/cache for avatars instead of embedding them as byte arrays in the ViewModel for the UI.
